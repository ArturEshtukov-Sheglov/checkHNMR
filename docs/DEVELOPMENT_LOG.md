# Development log

How the tools are improved, and on which data. The tools are rule-based: nothing is learned automatically.
Each entry is a failure found on some data, the class of texts it stands for, and the rule changed or added.
**Every data source named here is development data**: the accuracy of a version is measured only on data
that does not appear in this log (OSF registration doi:10.17605/OSF.IO/EQ9AH, Update 1 section 2(c)).
The details of each change are in CHANGELOG.md.

## Journals of the study: never development data

Org. Lett., Angew. Chem. Int. Ed., Eur. J. Org. Chem., Tetrahedron Lett., Chem. Commun., Nature Communications and
Communications Chemistry (any year; the last three added 2026-10-25, in the main list of the survey) are the journals of the survey. Their SI are not used to develop the tools, so that the measured accuracy is not tuned to their styles.
`fetch_oa_si.py` refuses to download them. Exception recorded earlier: the 201 Org. Lett. SI of the survey sample
were used for regression checks of V2/V2.1 (see the rows above); they belong to the study, not to a test set.

## How an entry is made

1. A failure is found (real SI, stress test, user report).
2. The author decides what the correct reading is.
3. The rule is changed so that the whole class of texts is read, not only the example.
4. A test with an invented example of the class is added; all tests and the self-test (`run_all.py --selftest`) must pass.
5. The effect on the 201 Org. Lett. SI is checked (for information: these are development data too).
6. The entry is added here and in CHANGELOG.md.
